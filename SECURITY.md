# Seguridad y reporte responsable — ADPHOR

**No publique vulnerabilidades explotables, credenciales, tokens o datos personales en issues y PR públicos.**

Si GitHub ofrece **reporte privado de vulnerabilidad** para este repositorio, utilícelo; de lo contrario, acuerde un canal privado con el propietario antes de transmitir evidencias sensibles. No se publica una dirección personal no verificada.

Un reporte debe contener el alcance y SHA afectados, impacto, pasos mínimos de reproducción sin datos reales y mitigación sugerida. Nunca adjunte archivos originales privados de José, copias de Drive o expedientes de copropiedades.

Principios: autorización de servidor y RLS, separación entre edificios, MFA cuando corresponda, Storage privado, mínimo privilegio y ninguna clave de servicio en frontend.

Esta política es una guía documental: **no instala controles ni certifica seguridad real**. Véase [Seguridad y privacidad](docs/SEGURIDAD_Y_DATOS.md).
